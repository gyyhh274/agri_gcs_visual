# 诊断工具

联调/排障用的独立脚本。都是**只读或可逆**的：不会删除相机文件，
改动了云台姿态的脚本结尾都会复位。

## 用哪个脚本，在哪台机器上跑

| 脚本 | 运行位置 | 用途 |
| --- | --- | --- |
| `siyi_probe.py` | 均可 | **只读探测**：状态/姿态/模式/变倍（最安全的第一个命令） |
| `verify_gimbal_commands.py` | 地面站 | 逐条验证拍照/录像/变倍/模式切换（可逆操作自动复原） |
| `test_rotate_cmd.py` | 地面站 | 测定 `0x07` 转向的方向约定（判断左右是否接反） |
| `recover_stuck_rotate.py` | 地面站 | 检测并解除"云台持续转动"卡死状态 |
| `recover_soft_reboot.sh` | **机载电脑** | 命令服务挂死时的恢复：发 `0x80` 软重启并等待 |
| `check_tfcard.py` | **机载电脑** | 确认 TF 卡是否在位（`0x0B`/`0x0A` 交叉验证） |
| `check_photo_flow.py` | **机载电脑** | 完整拍照链路：拍照 → 文件列表 → 下载校验 |

**为什么有的必须跑在机载电脑上**：相机在 `192.168.144.0/24`，
只有机载电脑能直达；这类脚本直接访问 `192.168.144.25`。
其余脚本走机载电脑上的中转（`192.168.2.113:37260`），地面站即可运行。

## 常用命令

```bash
# 只读探测（默认走中转；也可传相机地址在机载电脑上直连）
python3 siyi_probe.py                      # 经中转
python3 siyi_probe.py 192.168.144.25       # 机载电脑上直连

# 云台指令逐条验证（会小幅转动，结束自动复原）
python3 verify_gimbal_commands.py

# 转向方向排查（画面往哪边动才是真相，别只看角度数值）
python3 test_rotate_cmd.py

# 云台停不下来 / 一直在转
python3 recover_stuck_rotate.py

# 相机命令服务挂死（UDP+TCP 都不响应，但视频正常）
bash recover_soft_reboot.sh                # 在机载电脑上执行

# 确认 TF 卡 / 拍照链路（在机载电脑上执行）
python3 check_tfcard.py
python3 check_photo_flow.py
```

## ⚠️ 两条纪律

1. **永远不要发 `0x00` 心跳**：SDK 规定心跳仅 TCP 支持，对 UDP 发送会让
   相机的命令服务挂死（实测约 9 分钟无响应）。`0x80` 软重启可恢复。
   中转服务会主动丢弃这类帧。
2. **不要在中转运行时用别的工具抢占相机**：A8 mini 的 UDP SDK 是单客户端模型，
   多个客户端同时连会互相截胡（表现为随机超时、读数错乱）。
