# 从地面站启动机载程序

更新日期：2026-10-18。入口为「系统设置 → 机载程序」，连接设置顶部也有快捷入口。

**连接管理、启动飞行栈、上传航线、起飞和开始任务是不同操作。** 本页面启动飞行栈固定使用 `MISSION_SOURCE=remote` 和 `--start-only`，不会发送解锁、起飞或开始航线指令。飞行栈无需 RViz 或远程桌面即可启动。

## 按当前设备配置使用

机载端需先具备配套 `sh_files/module_manager.py`、已编译的 ROS 工作空间，以及从 Mac 可用的 SSH 公钥登录。管理连接使用实际地址，不读取 `~/.ssh/config` 中的 `Host ly` 别名或自定义 IdentityFile；密钥需能通过 SSH 默认密钥位置或 ssh-agent 使用。不在地面站保存 SSH 密码。

可先在 Mac 终端验证登录；首次连接应核对并接受正确的主机指纹：

```bash
ssh -F /dev/null ly@192.168.2.112
```

1. 打开新版地面站，进入「系统设置 → 机载程序」。填写主机 `192.168.2.112`、用户 `ly`、工程目录 `/home/ly/Documents/diff-planner-A8miniV2`。
2. 点击「连接机载」。这一步只建立管理连接和任务 SSH 隧道，不启动飞行或识别模块。
3. 选择「仅航点飞行」，或按下表勾选所需功能，再点击「启动所选模块」。勾选和选择预设本身不会启动程序。
4. 查看飞行栈状态和日志。相关节点注册后，地面站会尝试连接任务网关；需收到有效机载遥测才显示无人机已连接。
5. 切换到任务页，按[室内航点说明](INDOOR_MISSION.md)核对坐标、上传航线、手动起飞悬停，再开始任务。

功能选择会保存到本机；下次打开仍需明确连接、启动。只使用云台或识别时，可不选择飞行栈。

## 六个选项及依赖

| 选项 | 启动内容或作用 | 依赖与结果 |
| --- | --- | --- |
| 飞行栈 | MAVROS、雷达定位、EKF、规划、控制和任务网关 | 默认不带云台、YOLO、RViz；仍需单独触发起飞和开始任务 |
| 云台控制 | 机载云台 ROS 节点，接收云台动作 | 可独立启动；启动节点本身不会自动旋转 |
| YOLO 识别 | 读取视频、加载模型、后台检测 | 需要有效视频源和模型；不依赖云台节点，不弹识别窗口 |
| 起飞自动录像 | 监听飞行事件，调用原有云台录像逻辑 | 自动勾选云台；缺少有效飞行状态时等待，不自动启动飞行栈；原始录像保存到相机卡 |
| 保存识别视频 | 保存带检测框的视频 | 自动勾选 YOLO；保存到机载识别配置指定的目录 |
| RViz 调试 | 单独启动 RViz | 需要机载图形桌面与访问授权；退出 RViz 不停止飞行栈 |

取消云台会同时取消「起飞自动录像」；取消 YOLO 会同时取消「保存识别视频」。已运行的云台或 YOLO 不会因为取消勾选而停止；修改其录像选项，需要先明确停止对应模块，再重新启动。无需为了启用识别而重启飞行栈。

预设选择如下，录像始终另选：

| 预设 | 飞行栈 | 云台 | YOLO |
| --- | --- | --- | --- |
| 仅连接 | 不选 | 不选 | 不选 |
| 仅航点飞行 | 选 | 不选 | 不选 |
| 地面识别调试 | 不选 | 选 | 选 |
| 完整巡检 | 选 | 选 | 选 |

「仅连接」是清空启动选择的预设；建立管理连接仍需点击「连接机载」。启动所选模块只增加所选工作模块，不会停止未勾选但已经运行的模块。

云台模块启动不等于航点自动扫描。当前 remote 航点协议尚未接入逐航点云台旋转/扫描动作；YOLO 检测结果也不会仅因勾选而自动改变飞行路线。

## 三条连接分别代表什么

| 界面或链路 | 能证明什么 | 不代表什么 |
| --- | --- | --- |
| 机载管理已连接 | SSH 和机载后台管理可访问，可查模块、读日志、发启动请求 | 飞行栈或飞控已连接 |
| 任务网关连接 / 无人机连接 | TCP 协议遥测有效；无人机已连接还取决于飞控连接状态 | 已具备起飞或执行航线条件 |
| 图传实时 | RTSP 视频链路有效 | ROS、任务网关或飞控连接正常 |

管理端为任务隧道分配空闲本地端口，例如 `127.0.0.1:49837`，转发到机载 `127.0.0.1:8765`。**本地端口会变化**，连接设置在管理连接有效时自动显示并使用实际端口，不应再手填固定 `8765`。它不会占用、接管或终止已有隧道。

不使用模块管理、而是自行启动飞行栈时，可在 Mac 手动建立独立隧道：

```bash
ssh -F /dev/null -N -L 127.0.0.1:8765:127.0.0.1:8765 ly@192.168.2.112
```

此时连接设置才使用 `127.0.0.1:8765`；本地端口必须空闲，机载 protocol 2 网关也必须已经运行。隧道存在只说明转发进程存在，不能代替网关就绪检查。

## 状态、停止和断线

| 模块状态 | 含义与处理 |
| --- | --- |
| 未启动 | 没有检测到该模块运行 |
| 启动中 | 已发起启动，等待所需 ROS 节点注册 |
| 节点运行 | 所需节点已注册；飞行就绪看任务遥测，模型和视频就绪看日志 |
| 节点未齐，查看日志 | 启动等待超过状态检查期限；并不因此自动停止飞行栈 |
| 进程退出（代码） | 启动进程退出；点击该模块「查看日志」检查原因 |
| 正在收尾 | 正在停止进程、完成日志与 rosbag 收尾，等待结束后才能再启动 |
| 外部启动，不接管 | 检测到由其他终端或进程启动的节点；避免重复启动，管理器不接管停止 |

- 断开管理、关闭地面站、断开 VSCode/SSH 不会停止后台机载模块；地面站只关闭自己拥有的本地任务隧道和管理请求。
- 「停止」只停止管理器拥有的对应模块。停止飞行栈需读取新鲜的飞控状态，确认飞控连接、已落地且未解锁；状态缺失或条件不满足时拒绝。
- RViz、YOLO 的独立故障不触发飞行栈关闭。飞行核心节点自身的故障处理仍有效。
- 管理器为用户级后台进程，无开机自启和飞行自动重启。重启机载电脑后需重新检查状态、明确启动；不会恢复上一轮飞行任务。

## 从哪里看日志

优先在「机载程序」中点击对应模块的「查看日志」，或点击「基础 ROS 日志」。界面返回最近约 16 KiB；完整日志保存在机载电脑：

| 位置 | 用途 |
| --- | --- |
| `~/.local/state/agri-gcs-manager/<工程路径哈希>/flight.log` | 飞行启动脚本、依赖和退出原因 |
| 同目录 `gimbal.log`、`yolo.log`、`rviz.log` | 各模块输出 |
| 同目录 `roscore.log`、`manager.log` | ROS 基础与后台管理进程输出 |
| 工程目录 `flight_logs/<本次时间>/` | 飞行记录、关键事件和 rosbag，按实际生成文件分析 |

上述哈希由工程绝对路径计算，不是固定目录名。一次排查应对齐同一轮飞行的时间、飞行日志、模块日志和机载启动时间；ROS master 在其他位置启动时，本轮目录未必有 `rosout.log`。

## 常见问题与本次修复

| 现象 | 排查或已修复行为 |
| --- | --- |
| 管理连接成功，但任务网关连不上 | 若飞行栈未启动，这是预期状态；先启动飞行栈，再查网关节点及日志。只选云台/YOLO 不会提供飞行任务网关 |
| 图传正常，无人机仍未连接 | 分别检查任务隧道、网关和 MAVROS，视频并不经过任务网关 |
| 桌面终端能启动，VSCode/后台启动退出（1） | 检查 `flight.log`；已发现并修复后台缺少 `BD_LIST` 的问题，MID360 配置改由机载 `sh_files/onboard.env` 显式提供，不依赖交互式 `.bashrc`；更换雷达时核对该文件 |
| RViz 无法打开 | 检查图形桌面与授权，或取消 RViz；飞行栈可无界面启动，不能通过伪造显示地址解决授权问题 |
| 约 180 秒后飞行栈退出、任务网关断开 | 旧 `one_click_takeoff.sh` 在手动起飞模式仍等待地面检查并超时关栈。2026-10-18 已修复：默认/`--start-only` 不再执行该关栈超时；显式 `--takeoff` 检查失败时不发送自动起飞，并保留仍运行的飞行栈 |
| 网络或供电中断后状态消失 | 分别检查网络和机载电脑是否重启，不能仅凭断线认定任务正常结束；恢复连接后重新查询状态 |

180 秒修复只移除了错误的启动脚本退出路径，未绕过控制器或任务的起飞门禁，也不保证网络或供电不断开。最近一次飞行同时出现严重电压下降与高度下降，不能仅靠这项软件修复解释或解决电池问题。

机载 shell/Python/launch 文件修改无需重新编译 C++，在下次明确启动模块时生效；已经运行的进程不会自动替换。地面站 C++/QML 修改需要构建并重新打开新版应用。
