# M511S 舱门通信与联调

地面站已接入 Modbus TCP 客户端，提供协议验证、手动只读查询、舱门命令邮箱和状态监测。**真实 PLC 的寄存器映射尚未确认，初始地址留空；当前硬件验证仅达到有效 Modbus 异常响应，未进行寄存器写入或舱门动作。**

## 连接真实 PLC

1. 使用 `Start_GCS.command` 启动已构建的地面站，进入「系统设置 → 机巢设置」。通信面板位于本页顶部。
2. 填写 `192.168.2.8`、端口 `502`。Unit ID 默认 `1` 是试验值，仍应核对 PLC 项目设置。点击「连接 TCP」。旧演示配置 `192.168.1.100:8080` 不参与 PLC 通信。
3. 点击「只读协议验证」。这会发送 FC43 / MEI14 的基本设备识别请求，不依赖寄存器地址。有效的正常响应或异常响应均能证明 Modbus TCP 请求与响应链路；异常 `01` 表示功能不支持。
4. 获得厂商文档或 PLC 项目中的安全读取地址后，选择 FC01、02、03 或 04，填写地址和数量，再点击「读取一次」。协议验证成功与寄存器读取成功分别显示。
5. 尚未实现下面的 PLC 业务接口时，保持反馈和命令地址为空，不启用监测或写入。

地址输入统一为 **PDU 的 0 基十进制地址**，不接受 `D100`、`40001` 区号标记或十六进制文本。根据实际手册换算：只有手册明确使用从 1 编号的引用地址时才减 1；不能直接把 PLC 的 D/M 变量号当成 PDU 地址。

也可以在项目目录运行独立只读工具，无须安装 Python 第三方依赖：

```bash
python3 tools/plc_probe.py
```

默认只发送设备识别请求。`modbus_response_valid: true` 与 `register_read_ok: false` 可同时出现。脚本不会扫描地址、尝试写入或自动重试；读取参数必须同时指定 `--function` 和 `--address`，实际参数需先核实。

2026-11-01 实测 Mac 地址为 `192.168.2.28`，经 `en0` 到达 `192.168.2.8:502`。以 Unit ID 1 试探得到：

```text
TX 00 01 00 00 00 05 01 2b 0e 01 00
RX 00 01 00 00 00 03 01 ab 01
```

事务号、协议号、长度、Unit ID 与异常功能码均有效。设备不支持该识别功能，故未获取型号、固件或寄存器值。响应中回显 Unit ID 1 不足以证明设备会严格区分不同 Unit ID。

## 不接硬件验证完整流程

先在独立终端启动模拟器：

```bash
python3 tools/plc_simulator.py
```

模拟器仅监听 `127.0.0.1:15020`。回到「机巢设置」，在断开连接状态下点击「本机模拟配置」，再依次执行：

1. 连接 TCP → 只读协议验证（模拟器也返回异常 01）。
2. 选择 FC03，地址 `100`，数量 `4`，读取一次，应得到四个反馈字。
3. 点击「启动反馈监测」，等待递增心跳，反馈变为有效。
4. 勾选「已核对 PLC 映射、限位及联锁，允许本次连接写入」。
5. 在本页或任务页打开、关闭、停止舱门。模拟状态经过运动再到位，命令回执和到位反馈独立处理。切换页面不会断开连接。

模拟器地址 `100..103` 与 `200..201` 仅用于本机测试，**不是 M511S 的默认映射**。切回真实设备前，断开连接，将主机、端口改回真实参数，清空尚未确认的映射地址并保存。

本机只读寄存器验证命令：

```bash
python3 tools/plc_probe.py --host 127.0.0.1 --port 15020 --unit 1 --function 3 --address 100 --count 4
```

可分别重启模拟器验证故障路径：

```bash
python3 tools/plc_simulator.py --fault
python3 tools/plc_simulator.py --interlock
python3 tools/plc_simulator.py --freeze-heartbeat
python3 tools/plc_simulator.py --no-ack
python3 tools/plc_simulator.py --no-complete
python3 tools/plc_simulator.py --fragment-response
python3 tools/plc_simulator.py --response-delay 2
```

每次只启动一个使用同端口的实例。`--no-ack` 模拟动作发生但业务回执丢失；`--no-complete` 保持运动状态以验证到位超时。模拟器不提供真实电机保护逻辑。

## 待 PLC 开发的业务接口约定

以下约定已经由地面站和模拟器实现，PLC 项目需据此开发或与开发者协商调整。用户可以配置起始地址和反馈寄存器类型；字段顺序、位定义及命令编码是当前版本的固定业务约定。

| 本地配置 | 初始值 | 意义 |
| --- | --- | --- |
| host / port | 192.168.2.8 / 502 | TCP 目标 |
| unit | 1 | 可配置 0–255，需核对实际值 |
| statusFunction | 3 | 反馈采用 FC03 保持寄存器或 FC04 输入寄存器 |
| statusAddress | 空（内部为 -1） | 连续四个反馈寄存器的起始 PDU 地址 |
| commandAddress | 空（内部为 -1） | 连续两个保持寄存器的命令邮箱起始地址 |

反馈按下表读取，单字为无符号 16 位，大端传输：

| 相对偏移 | 字段 | 约定 |
| --- | --- | --- |
| +0 | 状态位 flags | 见下表 |
| +1 | faultCode | 0 无故障，非零故障；详细编号由 PLC 项目定义 |
| +2 | ackSequence | PLC 已处理的最近命令序号；业务接收不等于动作完成 |
| +3 | heartbeat | PLC 应用逻辑定时递增，例如每秒 +1，16 位回绕 |

| 状态位 | 值为 1 的含义 |
| --- | --- |
| bit0 | 开启到位 |
| bit1 | 关闭到位 |
| bit2 | 正在开启 |
| bit3 | 正在关闭 |
| bit4 | 故障 |
| bit5 | 联锁禁止动作 |
| bit6 | 急停触发 |
| bit7 | 远程控制就绪 |

bit8–15 预留，当前客户端不解释。开、关限位同时有效或双向运动位同时有效均视为冲突，反馈立即失效并关闭写入。无到位和运动位时显示中间位置 / 已停止；断网、反馈过期或心跳未更新时显示未知。

命令邮箱通过 **FC16（0x10）一次写两个寄存器**：

| 相对偏移 | 字段 | 约定 |
| --- | --- | --- |
| +0 | command | 1 开启、2 关闭、3 停止 |
| +1 | sequence | 1–65535，按 PLC 最近回执生成下一序号 |

PLC 应把这两个字作为完整命令处理。基于新序号触发一次动作，重复序号不重复执行；更新回执序号，再由真实限位与控制状态更新反馈。PLC 启动时不得重放保留区中的旧命令，应清理邮箱或建立新会话基线。多客户端控制需要 PLC 端独立仲裁，当前地面站接口按单控制端设计。

网络写响应仅表示邮箱写入被响应。地面站随后等待 `ackSequence` 匹配，再等待对应到位反馈。打开、关闭、停止后都不会直接改写本地舱门状态。停止命令允许在已有运动命令尚未完成、联锁、故障或急停触发时发出，但仍要求当前连接、有效反馈、写入许可和空闲请求通道。

## 失效处理与现场职责

- TCP 连接超时 2 秒；单个请求超时 1.5 秒；同一连接最多一个请求在途。TCP 响应支持分片，严格检查 MBAP、功能码、字节数量和 FC16 回显。
- 监测每 500 毫秒发起一次四字反馈读取，请求未结束时跳过本次轮询，不排队积压。
- 反馈超过 2 秒、心跳超过 5 秒未变化、异常反馈或冲突反馈时，动作命令不可用并关闭写入许可。首次监测必须看到心跳实际变化才能启用写入；恢复后须手动重新启用。
- 命令业务回执超过 3 秒，或动作自下发起超过 30 秒仍未完成，进入结果未知。保留待确认命令，不自动重发，不因超时自动发送其他动作。
- 断开、连接失败或响应解析失败会关闭写入许可。重连后不自动监测、不重放邮箱、不恢复写入许可。
- 结果未知时，核对现场；通道仍有效且写入许可仍在时可以发送停止。恢复后点击「确认现场已停止」，需要新鲜的静止反馈、空闲通道及匹配的命令回执，随后重新启用写入。不能把这次人工确认当作现场急停。
- 写入许可、连接与监测状态不持久化。配置保存至 Qt 用户设置 `NestPlcV1/configuration`，不会修改 PLC 工程或网络参数。
- 地面站崩溃、Wi-Fi 中断时无法保证网络停止送达。PLC 必须独立实现电机互锁、限位、急停、运动超时与通信失效保护。当前接口只有 PLC → 地面站心跳，没有地面站租约心跳；若需要检测“界面仍运行但无人持续控制”，需在 PLC 开发阶段扩展租约协议。
- PLC IP 持久化仍待处理：先备份项目，再检查项目内 Ethernet Parameter Settings，按厂商流程同步 `192.168.2.8/24` 并验证重新上电后的地址。本次没有下载 PLC 程序或重启 PLC。
