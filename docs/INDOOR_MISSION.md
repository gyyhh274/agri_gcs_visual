# 室内局部地图与动态航点任务

使用 `world` 米制网格在地面站选点，通过 TCP JSON-lines protocol 2 上传到机载 ROS1 任务网关，再由 `multipointplan` 和 Diff-Planner 执行。

当前为源码首版：协议及坐标逻辑已有检查，尚未完成 Qt5/ROS1 完整编译、规划器仿真和实机验收。此仓库包含地面站端；运行任务需要配套的机载 remote 模式与 protocol 2 网关。原 protocol 1 网关仍只能提供只读遥测。

## 地图与定位

无需 GPS，但需要雷达或视觉里程计提供有效的 `world` 位姿。网格只是选点画布，不提供定位、障碍物信息或规划轨迹。

- 默认每格 1 m，缩小时每格 2 m。X 向右、Y 向上，对应本次定位坐标轴，不代表东/北或机头方向。
- 点击“添加航点”后在网格选点，拖动航点修改 X/Y，编辑 Z 和悬停时间。
- 默认 Z=1 m、悬停 2 s。Z 是 `world.z`；只有地面对应 Z=0 时，Z=1 才表示离地约 1 m。
- 青绿色点显示有效机载里程计中的无人机位置；“定位无人机”将视口移到该位置。
- 橙色连线表示航点顺序，实际避障地图和轨迹继续在 RViz 查看。
- 室内航线单独保存在 `IndoorMissionV1`，与原有经纬度航线分开。室外航线仍只支持本地编辑。

定位重启或原点改变后，重新核对 RViz 中的原点、轴向和高度，再确认并上传航线。快速重置和小幅坐标变化不保证被自动识别，应按机载流程重启完整定位、任务和控制链路。

## 演示步骤

1. 启动配套机载 remote 任务模式与网关；通过 SSH 隧道将机载 loopback 的 8765 端口映射到地面站。
2. 在连接设置填写 `127.0.0.1:8765`，确认收到有效定位和任务状态。
3. 在网格选点，编辑局部高度，勾选已核对本次定位坐标，点击“上传航线”。上传不触发起飞。
4. 使用原遥控器流程起飞悬停，等待机载任务就绪，再点击“开始任务”。
5. 执行中编辑、拖动、删除尚未执行的后续航点，或继续追加航点，然后点击“更新后续航点”。机载确认后界面采用新版本，后续目标交给 Diff-Planner 规划；当前路段或悬停动作继续执行。
6. 查看机载版本、当前航点、悬停阶段和已完成数。起飞、降落及人工接管沿用原流程。

开始仅在机载任务、版本、定位会话和当前编辑航线均匹配时启用。开始前编辑航线后需重新上传；执行中通过“更新后续航点”提交草稿，不重新开始任务。

已完成航点和当前执行/悬停点锁定，禁止修改、删除；执行中不能导入或清空整条航线。地图中灰蓝色表示已完成，青蓝色表示当前点，橙色表示后续点，选中点为黄色。尚未提交的变更显示“待更新”，不会覆盖真实执行状态。

点击“撤销草稿”可恢复最后一次获机载确认的航线。若编辑时任务推进，草稿改动的点已变成当前点，更新按钮会禁用并提示先撤销草稿再编辑；机载还会按命令抵达时的最新进度再次检查，拒绝过时修改。

断线重连后先查询机载状态并重新核对定位坐标。当前页面保留已确认航线，只有定位会话、任务 ID 和版本均匹配时才恢复更新权限。更换页面、应用重启或其他客户端更新导致本地无法确认完整航线时，执行中只显示机载进度。命令不自动重发，也不会仅凭遥测中的新版本把未收到 ACK 的更新标为成功。

支持上传、开始、查询和执行中更新后续航点。暂停、取消、立即改飞当前目标、自动返航、界面降落和航点云台动作未接入，相关飞行按钮禁用。速度由机载规划器配置，未提供逐点速度设置。

## 网关约定

地面站保留 protocol 1 只读遥测支持。protocol 2 增加任务状态及命令确认，所有消息为 UTF-8 JSON，以换行分帧，单帧上限 64 KiB，单任务最多 200 航点。

命令操作为 `upload`、`start`、`get_status`、`update`，包含 request_id、map_session_id、mission_id 和 revision。上传及更新使用 `frame_id=world`，航点字段为 id、x、y、z、hover_sec。

`update` 沿用当前任务 ID 和定位会话，revision 为已确认版本 + 1；`replace_from` 是从 0 开始的数组索引，`waypoints` 仅包含从第一个改动位置开始的新后缀。保留前缀由机载保存，不重复发送。执行中要求 `replace_from > completed`，保留当前点；索引等于原 total 表示追加，空后缀表示删除未来点。更新后航点总数仍不得超过 200，坐标和高度遵守机载发布的范围。示例：保留第 1、2 点，替换第 3 点及其后续航点：

```json
{"type":"command","protocol":2,"request_id":"unique-request-id","operation":"update","map_session_id":"current-session","mission_id":"current-mission","revision":2,"frame_id":"world","replace_from":2,"waypoints":[{"id":3,"x":2.0,"y":1.0,"z":1.0,"hover_sec":2.0}]}
```

该功能需要配套机载 `feat/gcs-dynamic-mission` 中支持 `update` 的网关和任务节点。较早的 protocol 2 网关可能拒绝该操作；拒绝不会提交本地草稿。ACK 表示任务层接受新航线，后续航点开始执行时才成为规划器目标，并非立即中断当前路段。

任务状态包含定位会话、任务 ID/版本、state、current_waypoint_id、completed、total、reason、odom_fresh、flight_ready、world_x/y/z、max_abs_xy、min_z、max_z。state 支持 IDLE、READY、FLYING、HOVERING、COMPLETED、FAILED、LANDING。完整字段及校验逻辑见 GroundLink 和测试。

命令确认超时为 5 s，遥测超时为 3.5 s。超时提示“结果未知”，不等同于机载拒绝或任务停止。ACK 仅表示任务层接受，不保证规划成功。仅 Wi-Fi 断线时，首版机载端在定位和控制正常的情况下继续已开始的任务；自动断线悬停需要后续可恢复暂停机制。
