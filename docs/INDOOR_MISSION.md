# 室内局部地图与动态航点任务

更新日期：2026-10-18。使用 `world` 米制网格选点，经 TCP JSON-lines protocol 2 上传到机载 ROS1 任务网关，再由 `multipointplan` 和 Diff-Planner 执行。需要两端配套程序；protocol 1 只提供只读遥测。

**上传航线不触发起飞；更新或追加航点也不等于开始续飞。** 机载程序启动、SSH 隧道和连接排查见[机载程序说明](ONBOARD_MODULES.md)。

## 核对坐标和高度

无需 GPS，但需要雷达或视觉里程计提供有效的 `world` 位姿。网格是选点画布，不显示障碍物、可通行区域或实际规划轨迹。

- 网格默认每格 1 m，缩小时每格 2 m。画布 X 向右、Y 向上，对应本次定位坐标轴，不代表东/北或机头方向。
- `world` 为固定局部坐标；机体 ROS FLU 坐标是 X 向前、Y 向左、Z 向上。**航点 X/Y 都为正，不能推断飞机应向观察者或机头的右边飞。** 还需看飞机当前位置和朝向，以及世界坐标轴与现场方向的关系。
- “添加航点”后点击网格选点，拖动航点修改 X/Y；表格可编辑 Z 与悬停时间。
- 默认 Z=1 m、悬停 2 s。Z 是 `world.z`，仅当地面对应 Z=0 时，Z=1 才约为离地 1 m。机载接受范围以页面显示为准。
- 青绿色点是有效里程计中的飞机位置；“定位无人机”改变地图视口，不修改航点坐标。橙色连线仅表示执行顺序，实际避障与规划轨迹可在 RViz 查看。
- 室内路线保存在独立的 `IndoorMissionV1` 配置中；室外 WGS84 航线仍仅本地编辑，不会自动转换为 `world`。

定位重启、原点或轴向改变后，应重新核对坐标、当前飞机位置和高度。快速重置与小幅变化不一定被自动检测；不要把旧会话的航线直接当作当前可飞航线。任务复位也不能修复定位本身的坐标错误。

## 上传并开始一轮任务

1. 在「系统设置 → 机载程序」连接机载、启动飞行栈，等待任务网关和有效定位遥测。使用管理连接时，连接设置自动使用实际分配的本地隧道端口。
2. 在地图建立或编辑航线，核对原点、轴向、Z 和顺序，再勾选“已核对本次定位原点、X/Y 方向和高度”。
3. 点击“上传航线”，等本轮成功回执，检查机载版本、航点数量及 `READY` 状态。上传不会解锁或起飞。
4. 按机载遥控器流程起飞悬停，等待定位、控制器和规划器就绪。
5. 点击“开始任务”。仅在本地航线、已确认机载版本、任务 ID、定位会话均匹配且 `flight_ready` 有效时启用。

起飞前修改已上传的航线，需要重新上传。上次上传成功、当前有地图图形、SSH 连接成功，都不能代替本轮机载确认。

## 飞行中添加、修改或删除航点

任务处于 `FLYING` / `HOVERING` 时，可编辑、拖动、删除尚未执行的后续航点，或在末尾追加，然后点击“更新后续航点”。

机载确认新版本后，当前路段或悬停动作继续，随后执行新后续航点。**只在地图新增航点不会发送更新，也不会立即改飞当前目标。** 已完成和当前执行/悬停点锁定，执行中不能清空或导入整条路线。

已完成点为灰蓝色、当前点为青蓝色、后续点为橙色，选中点为黄色。草稿变更显示“待更新”，不覆盖真实执行进度。如果编辑期间任务推进，改动点进入当前执行范围，更新会被禁用；点击“撤销草稿”恢复最后获机载确认的航线，再编辑后续点。机载还会在命令抵达时复核进度。

## 完成后追加并开始续飞

1. 原任务变为 `COMPLETED` 后保留已完成点，在末尾添加新点。
2. 点击“追加后续航点”，等待确认。任务 ID 保持一致，版本递增，已完成计数保留，任务回到 `READY`。
3. 点击“开始续飞”。例如原 3 点已完成、追加第 4 点，只从第 4 点继续，不重飞前 3 点。

追加确认不会自动开始。飞机需要仍在空中、OFFBOARD，控制器悬停就绪，且定位与规划器有效。降落锁定后应使用下一节的地面复位流程。

任务完成后如需换整条路线，可明确清空或导入新航线，再重新核对上传；它是新任务，进度从零开始。清空本地路线本身不向机载发送取消、降落或新航线命令。

## 返航到哪里，是否自动降落

RC8 上档 → 中档，或地面站“返航”，请求返回本次定位会话中起飞解锁前记录的地面 X/Y，保持触发返航时的 `world.z`，由 Diff-Planner 规划。到达后悬停，降落需另外触发。

返航会替换当前航点任务、生成独立返航任务 ID，不再继续原路线；返航期间拒绝航点更新，到达后可明确上传新任务。重复请求不会反复重启返航，旧任务、版本或定位会话的请求会被拒绝。

没有有效起飞前位置、定位失效或重置、未在空中、控制器/规划器未就绪、降落或故障锁定时，机载会拒绝并给出原因。起飞点不等于网格 `(0,0)`；空中重启也不会把当前空中位置当作起飞点。

当前配套遥控器流程：RC8 下 → 中请求起飞，中 → 上开始已准备航线，上 → 中请求返航，其他档位 → 下请求降落；仍需满足 CH5/CH6、摇杆回中和机载门禁。遥控器具体映射以机载配置为准。

## 降落锁定与下一轮飞行

“降落锁定”表示机载已进入降落停止流程，禁止继续上传、开始或更新飞行任务，避免旧轨迹恢复。落地后该锁不会因 TCP 重连、编辑航点或重复点开始而自动解除。**此时允许编辑、删除、清空本地草稿，但这些操作不会解除机载锁。**

新版机载支持地面任务复位，无需为普通降落锁定每次重启整栈：

1. 确认已落地、`ON_GROUND`、`armed: False`，CH8 保持下档，飞控及遥控器状态有效。
2. 使用已配置的 CH9/SWB：从当前端档拨到另一端保持 2 秒，再拨回；或在机载工程终端执行 `./sh_files/reset_mission.sh`。
3. 确认日志出现 `RC CH9: mission reset succeeded`，或服务返回 `success: True`。任务应回到 `IDLE`、航点数为 0，定位会话更新。
4. 在地面站重新核对当前坐标，重新上传本轮完整航线，等待本轮成功回执，再准备起飞和开始任务。

复位会清除机载旧航线、目标、轨迹和进度；即使飞相同路线，也必须在最后一次复位后重新上传。复位不是起飞，也不会恢复旧任务。CH9 必须实际传到接收端；缺少通道时使用终端方式。规划器强制急停或定位异常仍需排查，不能反复复位掩盖故障。地面站目前没有独立的任务复位按钮。

## 切页、保存、重启与断线

| 操作 | 保留或恢复什么 |
| --- | --- |
| 切换任务、日志、设置页面 | 保留页面实例、当前草稿和本地确认状态；机载遥测变化仍会使过期确认失效 |
| “保存航线” | 保存本地室内路线，供应用重启读取，不代表已上传 |
| 收到匹配的上传/更新成功回执 | 保存该次获确认的路线，避免重新打开后回到旧路线 |
| 完全退出再打开地面站 | 恢复已保存路线，不恢复坐标核对和机载任务确认，不自动重发命令 |
| TCP 断线重连 | 查询机载状态、重新核对坐标；仅任务 ID、版本、会话和本地确认路线仍匹配时恢复更新权限 |
| 机载复位或定位会话改变 | 旧确认失效，需要重新核对并完整上传 |

如果拖到右边、切页后又回到旧的左侧路线，应核对是否仍在使用旧地面站进程；新程序已保留页面，并在匹配成功回执后保存路线。地图平移只改视口，拖动航点才改 X/Y；重启后恢复路线不等于恢复视口，也不等于机载已确认。

执行中缺少匹配确认路线时，界面只显示机载进度，不根据遥测版本擅自认定本地草稿已接受。确认超时提示“结果未知”，不代表机载拒绝或停止；应重新查询状态，命令不会自动重发。仅 Wi-Fi 断线时，机载在定位和控制正常的情况下可能继续已开始的任务，不能把地面站断开当作降落或停止。

## 网关约定与功能边界

所有消息为 UTF-8 JSON，以换行分帧，单帧上限 64 KiB，最多 200 航点。protocol 2 命令为 `upload`、`start`、`get_status`、`update`、`return`，使用 `request_id` 关联确认，并校验 `map_session_id`、`mission_id` 和 `revision`。完整字段与校验见 [GroundLink.cpp](../src/GroundLink.cpp)和[通信测试](../tests/tst_ground_link.cpp)。

上传及更新使用 `frame_id=world`，航点含 `id`、`x`、`y`、`z`、`hover_sec`。`update` 沿用任务和会话、版本加 1，`replace_from` 为从 0 开始的后缀起点。执行中必须保留已完成和当前点，要求 `replace_from > completed`；完成后的追加保留已完成前缀，要求 `replace_from >= completed` 且确实还有未完成点。索引等于原 total 表示末尾追加；执行中空后缀可删除未来点。

保留前两点、替换第 3 点及后续点的请求示例；标识符需取当前任务实际值：

```json
{"type":"command","protocol":2,"request_id":"unique-request-id","operation":"update","map_session_id":"current-session","mission_id":"current-mission","revision":2,"frame_id":"world","replace_from":2,"waypoints":[{"id":3,"x":2.0,"y":1.0,"z":1.0,"hover_sec":2.0}]}
```

机载范围由遥测中的 `max_abs_xy`、`min_z`、`max_z` 约束。状态含 IDLE、READY、FLYING、HOVERING、COMPLETED、FAILED、LANDING；返航通过任务原因显示“正在返航”或“已返航，悬停中”。ACK 仅表示任务层接受，并不保证规划或飞行成功。

命令确认超时 5 s，遥测超时 3.5 s。旧 protocol 2 网关未必支持更新、完成后续飞或返航；两端必须配套。当前没有接入界面暂停、紧急降落、立即改飞当前点或逐航点云台动作，相关按钮禁用。速度由机载规划器配置，未提供逐点速度设置。
